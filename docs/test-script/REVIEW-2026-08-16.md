## Fix 1 — the language toggle is not on Ako, it is in the header

`build-test-script.mjs:138`, the note that begins *"A note on language."*

Currently ends:

> Check whichever language the interface is showing; the toggle is on the Ako
> screen.

**Why it is wrong.** `src/components/SiteHeader.tsx:31` declares `/` a bare
route and returns `null` there, so the header — and the only language control in
the product — renders on every screen **except the map**. Confirmed in a
browser: `header.site-header` is present on `/report` and `/ako` reading
`Antas | Filipino | English`, and absent on `/`.

Saying "on Ako" is not false, but it is the one phrasing that strands a tester:
the map is where they start, and it is the single screen where the control does
not exist.

Replace the final clause with:

> Check whichever language the interface is showing. The toggle sits in the
> header, on every screen except the map — the map has no header, so switch
> language from Gabay, I-report, Ako or Tulong.

The same wording problem is in summary row 6 (`:240`), *"Switch between Filipino
and English on Ako"*. Either leave it — Ako does work — or widen it to *"Switch
between Filipino and English from the header"*.

## Fix 2 — summary row 3 can be marked Pass when the app has actually failed

`build-test-script.mjs:237`:

```js
["3", "Search - no match", "Type Zzqxwv in the search field", "No matches is shown, and nothing crashes", "", "Pass / Fail"],
```

**Why it is wrong.** There are two different messages, and they mean opposite
things:

| Condition | Filipino | English |
|---|---|---|
| Search ran, found nothing | `Walang tugma.` | `No matches.` |
| Search could not run at all | `Hindi makahanap ngayon. Subukan ulit.` | `Cannot search right now. Try again.` |

Both render in the same `.place-search-empty` slot in the same dropdown
(`src/components/PlaceSearch.tsx:198-201`). A tester who sees a message in a box
and reads the expected result as "No matches is shown" will tick Pass for a
search backend that is completely down.

This is not hypothetical — running the step locally against a stopped database
produced *"Hindi makahanap ngayon. Subukan ulit."*, and the row as written
accepts it.

Replace the expected result with the exact string:

```js
["3", "Search - no match", "Type Zzqxwv in the search field", "Walang tugma. (No matches.) appears - NOT Hindi makahanap ngayon., which means the search itself failed", "", "Pass / Fail"],
```

## Fix 3 — summary row 10 may be impossible to run

`build-test-script.mjs:244`:

```js
["10", "Report age", "Tap any pin on the map", "The reading shows its age, not only its depth", "", "Pass / Fail"],
```

**Why it is risky.** The seeded demo pins were removed from production on
2026-08-15 once the link started being shared. What is left is roughly six real
depth reports across the whole of Metro Manila. A tester opening the map is
likely to find no pin at all — and a row that cannot be run is a row that gets a
guessed Pass or a false Fail.

**Option (a) was taken** — the row now reads *SOS hold guard*. Option (b) is
recorded below in case you would rather have it back.

**(a) Replace it with something always present.** Applied. It exercises the most
important control in the product without sending anything:

```js
["10", "SOS hold guard", "Open Tulong, press and hold the button for about one second, then release", "The ring fills while held and resets on release; no SOS is sent", "", "Pass / Fail"],
```

Safe to run and safe to repeat: opening `/sos` writes nothing — the anonymous
session is created inside the submit handler, not on load — and releasing early
cancels. Even a full three-second hold does nothing without a photo attached.

**(b) Keep the row and tell the tester where to look.** Only workable if you
first check what is actually on the map that day, and it will rot the moment
those reports age out.

## Fix 4 — Test 2 left the tester's browser modified

Test 2 has them set location permission to Block. The handout's §7 says scripts
get swapped with a classmate and run on their machine, so the script should hand
the browser back as it found it. Add a final step after `:202`:

```
6. After the test, restore location permission to Ask so later tests are unaffected.
```

The redundancy between precondition 2 ("set to Block, or be ready to press
Block") and step 5 ("if the browser asks, press Block") is fine — leave it. It
covers both browsers that remember the choice and browsers that re-prompt.
